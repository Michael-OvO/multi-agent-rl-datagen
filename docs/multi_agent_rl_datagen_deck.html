02  /  The specification

What one unit of this data has to contain.

01
An executable world with inspectable state
Not a transcript, not a description. The reward has to be computable from what actually changed.
02
A role partition
Who may act on what, who may know what, and who may speak to whom. This is what makes the episode multi-agent rather than one agent with sub-calls.
03
A task with ground truth the roles must jointly satisfy
No single role can complete it alone — otherwise the partition is decoration and the episode teaches nothing about coordination.
04
A reward computed from terminal world state
Not from an opinion about the transcript. This is the requirement that decides the entire architecture.
05
Enough decision density to carry credit
The coordinator's high-consequence turns — whom to call, what to tell them, when to stop — have to be frequent enough that a GRPO-family update can attribute outcome to them.
Miss #4 and the reward is unverifiable. Miss #5 and there is nothing to optimise. Everything downstream is built to guarantee those two.
the quality bar, stated before anything is built
03  /  The decision everything follows from

Coordination has no off-the-shelf verifier. There are exactly two ways to get one.

Option A — design a coordination judge
You write the reward, so your tests agree with your errors.
The failure mode is silent. A hand-written coordination reward on this project's first task family returned exactly 1.0 on 12 of 12 runs — zero variance, zero advantage, zero gradient — because the task instruction stated its own optimal algorithm. Nothing in the reward reports that. Every gate was green.
Option B — inherit a programmatic verifier
Change only who can act. The reward keeps a validity someone else established.
The task, the ground truth, the world and the judge all come from a single-agent benchmark that already has them. A badly chosen constraint makes the task too easy or too hard — and that is a thing you can measure.
So the pipeline manufactures constraints, never rewards. No stage that follows can write to the judge — which is checkable by reading the code, not by trusting the claim.

What is inherited

Task · ground truth · world · judge

Four things that would otherwise each need designing and validating. All four arrive already validated by the benchmark's authors.

What is constructed

The role structure, and only that

Access, information, topology, budget. Four families of constraint, none of which has a path to the reward function.

What is measured

Yield, per cell, at five seeds

The output is a fraction of usable cells, not a promise of quality. A cell that fails the gate is discarded rather than shipped.

Stage 01  /  Admit

Four requirements a substrate has to clear.

Requirement 01

A verifier you did not write

Free, and already validated by somebody else — that is the whole of its value. Without it you are designing the reward again.

Requirement 02

Real, executable, installable

Not a description of a world. If you cannot pip install or docker pull it, you will end up building it.

Requirement 03

A reference solution per task

Derives the role roster and proves the task is solvable. Without it you are guessing which tasks qualify.

Requirement 04

Seams

An action surface that divides along role boundaries — apps, services, repositories, teams. No seams, no partition.

Admitted and carried end to end
Gaia2 / Meta AREwrite-action verifiers with a scripted mode that has no model in it · gold write actions plus full initial app state · a continuously running clock and asynchronous events · built explicitly for RL with verifiable rewards
Also clears the bar
SWE-smith  ·  τ-bench  ·  R2E-Gym
Admission is necessary, not sufficient. A database can ship a perfect verifier and still have every task collapse into a single seam. Stage 2 measures that rather than assuming it.

Stage 03  /  Partition

Construct the role structure by restricting access, not by adding reward.

Four constraint families
access
which apps a role may call at all — the coordinator gets none
information
role names only, or each specialist's real API catalogue
topology
who may address whom — star ships; chain is specified and unshipped
budget
a delegation target bN derived from the task's causal structure
The coordinator cannot act, so every effect in the world is produced by a specialist that never saw the task. The only channel between intent and effect is the brief — which is exactly the thing being trained.
forge/gaia2/render.py — one knob per cell, and no path from any knob to the reward
Stage 04  /  Target

Each cell prices exactly one ability.

Three abilities sit at the intersection of the largest measured failure mass, demonstrated RL trainability, and verification the inherited oracle already provides. Each is pinned to one knob, with the others held at neutral.
Ability 01 · whom to delegate to

capability-discovery

Knob: information = names. The coordinator knows its specialists exist but not what they can do.

Failure mass: MAST inter-agent misalignment, 36.9% of 1,600+ annotated failures.
Trains: ToolRL (NeurIPS 2025) — GRPO on tool selection, +17% / +15%.

Ability 02 · what goes in the brief

context-transfer

Knob: the partition alone. Catalogues on, budget off — only briefing quality varies.

Failure mass: MAST specification + misalignment ≈ 79%; agent-to-agent is every model's weakest Gaia2 category.
Trains: SWEET-RL — turn-level credit on collaborative tasks.

Ability 03 · when to spawn and stop

delegation-economy

Knob: a soft bN target from the causal write/read structure. Catalogues on, so discovery is neutralised.

Failure mass: MAST step repetition 15.7% + termination unawareness 12.4%.
Trains: Uno-Orchestra (2026) — Agentic-GRPO for selective delegation.

The one-knob rule. A knob delta is a per-ability price only while the other knobs sit at neutral. A names + budget cell moves two abilities at once and its delta prices neither, so the renderer will not emit one — and a stray sweep row is classified into exactly one bucket rather than double-counted.
Theory-of-mind and failure-recovery stay quarantined: no free oracle exists for either, and building one is precisely the failure mode this architecture exists to avoid.

Stage 05  /  Execute

Roll the episode out for real, and record every decision.

The delegation loop, per turn
→
Coordinator writes a brief
Natural language, addressed to one role. This is the trained artifact.
→
Specialist writes code against its one app
A real LLM doing real work — not a scripted stub, so the brief has to actually be sufficient.
→
Sandbox adjudicates the code
A static gate over what model-written code may touch; refusals are recorded with reasons.
→
Report returns to the coordinator
Brief, code, verdict and report are all persisted to a per-episode ledger.
What makes the rollout reproducible
Sidecar containerthe benchmark runs isolated behind a service boundary; the package pins the same versions the sweep measured
Execution contractobjective-actions-v1 — conditional writes wait for an observed trigger; one obligation, one side effect. Versioned, so a prompt change is a labelled experiment
Model paritya specialist below the coordinator's model class refuses to run unless an explicit flag labels the downgrade
Substrate isolationGaia2's harness needs pydantic 2, which the main environment does not pin, so it gets its own virtualenv
Packagingrendered to Harbor; a Gaia2 task carries its whole world in scenario.json and rebuilds from its own directory

Stage 06  /  Grade

The inherited verifier gives the reward. A shaping layer gives the gradient.

The reward — unmodified, terminal-state

The benchmark's own verifier

Gaia2 checks the agent's write actions against the scenario's gold write actions, and its scripted mode has no model in the loop. It was not written here, it is not touched here, and it cannot be reached from any constraint knob.

This is the only signal permitted near a gradient.

A binary pass/fail on a 16-write task is a very sparse reward. That is a credit-assignment problem, not a reason to invent a coordination judge — so the shaping is computed beside the verdict, never instead of it.
Deterministic shaping signals · no model involved
coveragefraction of gold write actions the episode reached at all
fidelityfraction of those reached with exactly correct arguments
partial rewardthe two combined, so a failed episode with a correct prefix is not flattened to zero
pivotthe index of the first fault, and its kind
economy rewardcompletion-gated auxiliary term on delegation count; exceeding bN never blocks completion
Pivot enables prefix replay. Freeze events[:pivot], resample the suffix. A 20-step episode that failed at step 6 becomes 14 steps of targeted training data instead of one discarded rollout.

Stage 07  /  Accept

The quality gate: a cell ships only if its score sits strictly between floor and control.

unconstrained control
VALID
the constraint bit, and the task survived it
do-nothing floor
DEGENERATE
Without this stage a generator cannot distinguish four situations that all print a number: the task is unsolvable · the constraint never bit · the harness is broken · coordination was actually learned.
VALIDfloor < score < control — usable RL data
DEGENERATEscore ≤ floor — no signal above doing nothing
NO_BITEscore ≥ control — the constraint changed nothing
NO_VARIANCEevery replicate identical — no advantage to learn from
CONTROL_FAILEDthe control is on the floor — the cell is unmeasurable
Five replicates minimum. A single draw has no variance to read, so SEEDS_FOR_YIELD = 5 refuses to report a one-seed run as a yield. Floor and control are both probed per task, not assumed.
the acceptance rule is substrate-independent: it needs only a score, a floor and a control
12  /  Data-quality controls

Six checks that run on every build.

Inheriting a verifier buys a correct judge. It buys nothing about the world around it — so each of these probes a way the environment could be paying for the wrong behaviour. All six are deterministic; none uses a model.
Control 01 · reward-protocol audit

Honest failure must not cost more than doing nothing

Measured: a truthful prose surrender scored 0.167 against a 0.333 floor, on 3 of 3 tasks — the environment paid more for a false completed.

the fix, at the protocol layer

A surrender verb, never a judge change

The contract gained FAIL ::, routed to status='fail' — a channel that prices at exactly the floor. Any substrate where honest failure scores below its floor now fails admission.

Control 02 · injection probe

A brief must not extract the reward token

Adversarial briefs are run against every specialist to check that a coordinator cannot talk its way to the answer instead of coordinating for it.

Control 03 · floor & control probes

Both reference points are measured per task

The do-nothing floor and the unconstrained ceiling are rolled out, never assumed. Only tasks whose control succeeds can price a knob at all.

Control 04 · parity & drift

The shipped task is the measured task

A gate fails the build if a committed container task no longer matches its generator; the model-parity rule blocks a silent specialist downgrade.

Control 05 · degeneracy quarantine

Zero-variance dimensions are pinned as failing

Two degenerate dimensions are kept rather than deleted, with xfail(strict=True) on their self-check — a permanent regression test against shipping a reward that discriminates nothing.

The binding constraint is not compute. Only tasks whose unconstrained control succeeds can price a knob — and that filter needs real rollouts. It cannot be derived by inspection, which is why corpus size and usable corpus size are different numbers.
Available today by reconfiguring real tasks rather than inventing them: 37 seamful scenarios × 4 cells = 148 specified cells, rendered by one command that calls no model.
Extrapolating the measured seam rate across Gaia2's full 1,120 scenarios suggests ~120 further seamful candidates before any parameterisation — an extrapolation, not a measurement, and four of six splits are still unfetched.
Prefix replay changes this economics directly: a failed 20-step episode currently costs a full rollout and yields one negative example; with a pivot index it yields a targeted resample of the suffix.

19  /  Next

Five things, in the order they unblock the rest. None of the cheap ones have been done.

01
A gold-replay ceiling and a do-nothing floor
Neither exists on this substrate, and without them the campaign cannot distinguish “hard scenario” from “broken harness”. A replay agent that issues the recorded write actions directly costs zero model calls and answers exactly that.
02
Repair the runtime before adding to it
40 malformed tool calls and 33 environment stops are 49% of the corpus, and neither is a coordination failure. Constrain the call syntax rather than requesting it; measure the clock budget against each scenario's horizon.
03
Disentangle judge from difficulty
Run the scripted verifier and the soft judge over the same scenarios. Right now the 0/128 versus 9/20 split has two explanations and no way to choose.
04
Then five replicates across the grid
37 scenarios × 4 cells × 5 seeds = 740 rollouts. The acceptance rule cannot report a yield at one seed — but this is the expensive step, and it is worth paying only once the control clears the floor.
05
Measure the seam classifier's own error rate
The rule that decides which scenarios coordinate is a designed classifier whose precision and recall are unmeasured. It is not safer for being a static provenance pass rather than a model — it is unvalidated in the same way, merely more greppable.
